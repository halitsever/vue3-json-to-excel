Comments in JSON files

By Halit Sever · 28 November 2026

Standard JSON has no comment syntax. Neither // nor /* */ appears anywhere in the grammar of RFC 8259, so a strict parser stops at the first comment. There are still a few ways to keep notes next to your data.

What happens when you add one

A file like this is not valid JSON:

{
  "port": 8080 // change for production
}

JavaScript's JSON.parse in Node.js 22 rejects it with:

SyntaxError: Expected ',' or '}' after property value in JSON at position 17 (line 2 column 16)

Python's json.loads stops at the same place:

json.decoder.JSONDecodeError: Expecting ',' delimiter: line 2 column 16 (char 17)

The converters on this site use the browser's own JSON.parse, so they report the same kind of error for a file with comments.

Option 1: a comment field

The portable fix is to make the note part of the data:

{
  "_comment": "Change port for production",
  "port": 8080
}

Every JSON parser accepts this. The cost is that the program reading the file sees _comment as a real key, so it has to ignore it, and a schema that forbids unknown keys will reject it. If you convert the file to a spreadsheet, the note becomes a column.

Option 2: JSON with comments (JSONC)

Some tools read their own config files with a parser that allows comments. VS Code calls this mode JSON with Comments and uses it for settings.json; the TypeScript compiler accepts comments in tsconfig.json. That works for those files only. The same file passed to JSON.parse or another program still fails, so do not rely on it for data that other systems read.

Option 3: JSON5 or YAML for hand-written config

JSON5 is a separate format that extends JSON with comments, single quotes and trailing commas. It needs its own parser library. YAML also allows comments with #. Both suit files that people edit by hand. For data that goes between programs, plain JSON remains the safe choice.

Option 4: strip comments before parsing

If you control the reader, remove comments first and parse the rest as JSON. Use a tested library for this rather than a regular expression: a naive pattern also deletes // inside strings, such as the one in "https://halit.org".

Check a file before you use it

Paste it into the JSON to Excel converter. If it parses, you see a table. If a comment or another syntax error is left, you see the parser's message. The rest of the syntax rules are in what is a JSON file.
